# 知识库格式

每份资料为 UTF-8 编码 `.md`，文件大小最多 1 MB。建议每份资料聚焦一个干员、一种机制或一个关卡，段落自包含；超长文档会自动切块。模板在 `templates/knowledge-template.md`，不要把未填写的模板导入资料目录。

## YAML 头部

开头必须是 `---`，头部结束也使用 `---`。字段中的日期请加引号，避免 YAML 将其解析为日期对象。

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| title | 文本 | 必填；例如“某干员二技能说明” |
| category | 文本 | 必填；干员、关卡、机制、养成、活动、其他之一 |
| tags | 文本数组 | 可选；建议加入常见昵称、缩写和别名，帮助词面检索 |
| source | 文本 | 必填；注明出处、原文链接或“个人实测记录” |
| updated | 文本 | 必填；引号包围的 YYYY-MM-DD，记录核实时间 |
| server | 文本 | 必填；例如“国服；某版本”，记录适用范围 |

标题与标签也会参与检索；所有规范元数据随切块保留。每个片段有 `chunk_id`、`start_index` 和原始文件名。块编号在重建后可能变化，不能当成稳定外部 ID。网页 [1] 是本轮引用顺序，不是全库块编号。

## 内容建议

干员资料：职业、定位、精英化条件、技能等级、技能/天赋效果、模组、适用场景、限制。

关卡资料：服务器与版本、地图/敌人、核心机制、阵容要求、部署步骤、可替换方案、失败点。避免只有“放在这里”之类依赖图片但没有文字坐标的描述。

机制资料：定义、公式、变量含义、前提条件、边界情况和算例。历史改动与当前机制分段说明，明确核实日期。

不要把未经核实的数据写成确定结论，也不要混合多个服务器的技能数据。来源不同或版本冲突时，拆成独立文档，标明适用条件，回答时据此辨别。

## 更新与删除

网页支持新增和批量导入，同名返回 409 防止误覆盖。已有文件可直接在 knowledge 目录中编辑或删除，点击“重建索引”生效。后台重建失败的单个文档会在知识库页显示原因。重启后会从原始文件重建，无需额外数据库。
