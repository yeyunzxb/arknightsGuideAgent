## 先跑一遍

1. 一键启动，不填密钥也能查看知识库、导入资料和阅读手册。
2. 配置密钥，点击连接验证，观察模型下拉列表。
3. 提问“物理伤害和法术伤害有什么区别？”，展开参考，检查 filename、chunk_id、source、updated。
4. 问一个库中不包含的具体技能数值。观察是否说明资料不足；即使检索到了相近资料也不应编造数值。
5. 新建对话，检查历史切换。刷新页面确认密钥已清除，而本地对话仍可打开。

## 修改一处，再观察

**切块：** 将 chunk_size 改成 350、chunk_overlap 改成 50。重启后端，比较片段数、原文是否完整、引用是否有足够上下文。字符数量不是 token 数量。

**别名：** 在某干员的 tags 中添加昵称，重建索引，再用昵称提问。比较命中情况。可以在 Python 中直接调用 `KnowledgeStore.search()` 查看分数，不请求模型。

**拒答：** 清空临时知识库或创建一个空目录，在启动后端前设置 `KNOWLEDGE_DIR` 为该目录。提问时返回空 sources、拒答文本与 done，且不会调用 DeepSeek。不要为这个练习删除真实资料。

**提示词：** 增加“先输出一句结论，再分点说明”。观察模型输出而非仅检查字符串。提示词约束不等于形式化事实验证。

**历史：** 同一会话先问一个干员，再问“那技能呢”。检索只用短问题可能缺对象，所以当前会用最近两条用户问题补充。试试多次切换话题，观察这种简化方案的局限，之后可增加单独的问题改写链，但会增加 API 请求。

## SSE 协议

`POST /api/chat` 返回 `text/event-stream`。事件顺序为 `sources`、若干 `token`、`done`；失败返回 `error`。没有候选时也有 sources（空数组）和 done。token 是增量字符串，不能用新片段覆盖已有文本。

浏览器停止按钮用 AbortController 取消 fetch。异常或停止的回答不会作为后续历史传给模型。后端并发模型生成限制为 3，最大输出 2400 token、超时 90 秒、不自动重试，避免不透明的重复付费请求。

## 当前边界与下一步

当前实现固定 RAG，与第 11 章一致。它借鉴第 15 章的引用和拒答，但没有第 12/15 章的 create_agent 工具循环、检查点或第 13/14 章的人审工作流。对当前“查资料再回答”的任务，固定流程容易观察和测试。

后续可以在理解当前流程之后，添加 `search_knowledge` 工具并用 `create_agent` 让模型生成检索参数，设置迭代上限并验证每轮确实调用了工具；或者替换本地 TF-IDF 为中文语义 Embedding。这两者分别改变决策流程和检索表示，不是同一件事。
